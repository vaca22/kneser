# halfexp 仓库审阅：结构、可靠性边界与下一步研究方向

> 审阅日期：2026-08-15  
> 审阅范围：并列目录 `kneser`、`semi_exp`、`kneser1950-paper`  
> 对应版本：`kneser@f207abb`、`semi_exp@633471f`、`kneser1950-paper@325b492`

## 结论摘要

这组仓库已经完成了一次重要转变：研究目标不再只是“数值构造满足
`f(f(x)) = exp(x)` 的 Kneser 半指数”，而是开始把连续迭代
`E_t(x) = exp^[t](x)` 当作一个可计算的几何对象。

目前最成熟的成果是 `kneser`：它把昂贵的 Kneser 构造移到离线构建阶段，
将运行时压缩成稳定、可复现的级数求值接口。`semi_exp` 则更适合作为方法探索
和失败记录，其中部分早期脚本不能作为可靠实现使用。下一阶段最有价值的工作，
不是继续单纯提高小数位数，而是把已经观察到的数值规律升级为带条件、误差界
和证明的数学命题。

## 1. 三层仓库结构

顶层 `/Volumes/dream/halfexp` 本身不是 Git 仓库，而是三个独立仓库的工作区：

- `semi_exp`：数值探索层。保存 Abel、Schröder、Carleman 和 theta-mapping
  等多条路线，包括失败模式、参数标定和高精度参考值。
- `kneser`：工程化与研究层。提供可复用 Python API、离线系数构建器、
  回归测试，以及连续迭代几何实验。
- `kneser1950-paper`：理论背景层。保存 Kneser 1950 年论文 OCR、双语导读
  和存在性、唯一性背景。

这三个仓库形成了较清晰的知识流：

```text
原始理论与证明背景
        ↓
多路线数值探索、证伪与参数标定
        ↓
可复用实现、回归测试与新几何实验
```

因此，阅读和使用时不应把三个目录视为同一可靠性等级。

## 2. 新洞察

### 2.1 核心对象正在从 `half_exp` 转向流生成元 `V`

在 Abel 坐标中，

```text
E_t(x) = sexp(slog(x) + t)
```

只是平移。拉回实轴后，它成为自治微分方程

```text
dx/dt = V(x)
```

的时间流，其中

```text
V(x) = sexp'(slog(x)).
```

这使多个看似独立的问题得到统一：

- `half_exp` 是该流的 `t = 1/2` 时刻映射；
- `slog` 是 `1/V` 的原函数；
- 局部拉伸因子满足
  `∂E_t(x)/∂x = V(E_t(x))/V(x)`；
- 运算路径 `x +_t y` 的端点斜率可改写为 `V` 的次可加或超可加判据。

所以，从研究价值看，`half_exp` 已经更像 `V` 所生成动力系统的一个截面，
而不是最终对象。证据集中在
`docs/research-findings-zh.md` 的第 1、2 节以及
`tests/test_research.py`。

### 2.2 `kneser` 的关键工程选择是“离线复杂，在线简单”

运行时模块 `src/kneser/_core.py` 不执行 Riemann 映射、Schröder 线性化或
theta 迭代。复杂构造由 `src/kneser/build.py` 离线完成，并写入
`src/kneser/_coeffs.py`。

运行时只包含三类操作：

1. 把参数归约到 Taylor 级数的基础区间；
2. 用 Horner 法求值预烘焙系数；
3. 用 Newton 法反演 `sexp` 得到 `slog`。

因此，主库的数学复杂度主要存在于系数的来源和构建证明义务中，而不是 API
的执行路径中。这种设计使普通求值快速、依赖少、结果可复现，也让构建器和
运行时能够分别测试。

本次复跑：

```bash
cd /Volumes/dream/halfexp/kneser
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=src \
  python3 -m pytest -p no:cacheprovider tests
```

结果为 `36 passed`。

### 2.3 `semi_exp` 是研究档案，不是第二套生产实现

`semi_exp` 中同时保留多条不同成熟度的算法。它的重要价值在于记录：

- Abel 局部展开的 Runge 型振荡；
- 朴素 Schröder 路线缺失 Kneser 分支所需的全局归一化；
- Carleman 种子可提供合理初值，但不足以单独保证 Kneser 分支；
- theta-mapping 的收敛行为和 `DEPTH` 标度律。

但其中至少一条早期路径已经不能可靠运行：
`plot_half_exp.py` 的 Schröder 实现在
`x = 0, 0.5, 1.0, 1.5` 上实测全部返回 `NaN`。

更重要的是，`tests/test_plot_half_exp.py::test_half_iterate_consistency`
只对非 `NaN` 结果执行断言。当四个复合值全部是 `NaN` 时，测试没有执行任何
有效比较，却仍然通过。因此，“测试全绿”在这里不能推出实现有效。

本次复跑得到：

```text
f(x):       [nan nan nan nan]
f(f(x)):    [nan nan nan nan]
有限复合值: 0 / 4
```

与此同时，该文件的四项测试显示通过，并伴随
`invalid value encountered in scalar divide` 警告。这是已复现事实，
不会影响 `kneser` 主库，但说明两套目录需要明确分级。

### 2.4 float64 的数学公式正确，但存在负尾表示边界

`kneser.half_exp(x)` 在 `x → -∞` 时趋向有限水平渐近线。随着 `x` 变得很负，
`half_exp(x)` 与该渐近值的差会小于 float64 的可分辨间隔。

实测结果：

```text
x = -20: f(f(x)) ≈ 2.0611536900e-9，仍能保留约 8 位相对精度
x = -40: f(f(x)) = 0.0，而 exp(x) ≈ 4.2483542553e-18
x = -50: f(f(x)) = 0.0，而 exp(x) ≈ 1.9287498480e-22
```

这不是 Kneser 构造失效，而是先计算 `f(x)` 时发生的信息丢失，第二次调用已
无法恢复。可执行的范围约定和边界测试见
[`precision-envelope.md`](precision-envelope.md) 与 `tests/test_boundaries.py`。

因此 API 的合理契约应是：

- 普通实数区间使用 `kneser.half_exp`；
- 极端负尾、严格相对误差或高精度恒等式使用 `kneser.hp`；
- 文档不应把 float64 下的 `f(f(x)) = exp(x)` 表述成无范围限制的数值保证。

### 2.5 项目已经进入“强数值、弱定理”阶段

现有实现能够高精度回答：

- Kneser `sexp`、`slog`、`half_exp` 和连续迭代的数值；
- 多个函数方程与流恒等式；
- `V` 的数值形状和最慢点；
- `x +_t y` 的非单调实例；
- 虚时间轨道的渐近旋转与收缩速率；
- 一定搜索高度内的 PSLQ 阴性结果。

但它不能仅凭数值回答：

- `V` 是否在全实轴严格凸；
- 运算路径非单调判据是否充要；
- 复时间渐近式是否有统一显式误差界；
- Kneser 常数是否无理、超越或代数独立；
- 一般方程 `f∘f = g` 在什么条件下可解。

这一区分非常重要。网格验证、80 位常数和 PSLQ 阴性搜索可以生成猜想或排除
低复杂度关系，但不能替代全局证明。

## 3. 本轮研究推进结果

以下结果均由新增 demo 实际运行得到。有限网格和有限时间窗仍是数值证据，
只有 `Fraction` 截断复合是在所声明有限阶环中的精确等式。

### 3.1 `V` 的解析导数扩域扫描

`demo_v_convexity_extended.py` 不再使用病态的微小二阶差分，而是从
`sexp` 的前三阶解析导数计算 `V''`，并用微分后的
`V(e^x) = e^xV(x)` 递推处理尾部。

- 840 个非均匀点覆盖 `[-100, 10^100]`；
- 没有采到 `V'' ≤ 0`；
- 微分递推最大相对残差为 `5.499e-68`；
- `V'` 只出现一次符号变化，细化根仍为
  `x* = 0.477743094766666...`。

这显著扩大了凸性证据，但扫描本身仍不是全局证明。剩余关键问题是把核心
Abel 区间上的导数符号变成解析证明或严格区间证书。

### 3.2 `D_t` 零切片与非单调判据

对 16 点正数网格的 136 个无序对，在 `t=j/96` 上检查运算路径。修正符号后的
端点候选与采样分类吻合 `136/136`。端点分类在 `q ∈ [1e-4, 24]` 上已是定理。
`D_t = 0` 也已是定理：每个 `t ∈ (0, 1)` 上是小支、间隙、大支两条严格递减的
对合，见 [`lemmas-round2-zh.md`](lemmas-round2-zh.md)。早先的四个
`D_(1/2)` 切片只是这两支的图示。

### 3.3 复时间二阶余项

`demo_complex_asymptotic.py --quick` 先在后段拟合

```text
E_it(x) - L = c(x)e^{itL} + d(x)e^{2itL} + ...
```

再在不重叠的早期窗口测量扣除一阶项后的余项。结果为：

```text
x=0: 衰减率 2.6743597492200731
x=1: 衰减率 2.6744735175028064
2 Im(L) = 2.6744714028613788
```

按 `2 Im(L)` 去指数后的包络跨度分别仅约 `1.00084` 与 `1.00018`，明显优于
按 `Im(L)` 缩放时约 800 的跨度。这是二阶 Koenigs 余项模型的强有限窗证据，
不是对所有 `x,t` 的统一误差界。

### 3.4 两个最小复合方程族

`demo_compose_family.py` 完成两端校准：

- 对 `g(x)=(9/4)x`，精确得到主实支 `f(x)=(3/2)x`；
- 对 `g(x)=e^x-1`，用 `Fraction` 精确验证
  `f(f(x))=e^x-1 (mod x^25)`。

第二项只证明指定分支的有限阶形式可解，不证明级数收敛，也不构成一般
`f∘f=g` 可解性理论。

完整数据、复现命令和更严格的事实/猜想/命题分层见
[`research-findings-zh.md`](research-findings-zh.md)。

## 4. 已完成的工程动作

1. `semi_exp` 的 NaN 空通过已改成三个 `strict xfail`：测试体现在完整要求所有
   值有限且满足函数方程；意外 XPASS 会使 CI 失败。
2. `semi_exp/ROUTES.md`、入口帮助和脚本头部已经按 reference、research、
   approximation、broken 分级；可靠绘图仅通过可选安装的 `kneser` 包。
3. `kneser` 已增加负尾精度契约和 float64/hp 边界测试，权威说明见
   [`precision-envelope.md`](precision-envelope.md)。
4. 两个独立仓库均已有分离的 GitLab CI；`kneser` 将研究测试标记为非阻塞，
   `semi_exp` 允许明确 xfail 但禁止空通过和 XPASS。
5. 数值研究文档继续区分事实、有限域证据、猜想和证明；新增常规测试只锁定
   低成本、范围明确且稳定的回归事实。

## 5. 总体判断

`kneser` 已经可以作为可靠的数值实验仪器；`semi_exp` 则保存了它为何采用
当前算法的研究历史。这个组合的独特价值，不只是提供半指数函数的一个 Python
实现，而是同时保留了：

- 方法为何成功；
- 替代方法为何失败；
- 参数如何标定；
- 数值结果如何转化为新的几何问题。

下一阶段最可能形成实质性成果的路线，是以 `V` 为统一对象，把凸性、运算路径
和复时间渐近中的至少一个数值规律升级为定理。继续增加精度仍有价值，但应服务
于严格误差控制和猜想筛选，而不应成为研究目标本身。
